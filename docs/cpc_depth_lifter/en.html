Depth Lifter reads a Python file and builds several versions of it, an index of
its functions and classes, and an index of its variables, so you can see how the
program is laid out. It parses source code; it does not run it.

Settings, backups, reports and the crash log all live beside the program (beside
the exe when compiled): cc_depth_lifter.json, the backups folder, depth_lifter_reports
and depth_lifter.log. If that folder cannot be written, a cc_depth_lifter folder in
AppData is used instead. Files or folders dropped on the exe icon (or given on the
command line) are processed like dropped files. Unexpected errors are written to
depth_lifter.log; the first three of a session also show a message.

While a file is read or built, a moving bar and a wait cursor show at the right of
the status line, and the status says which step is running, so a large file never
looks stuck.

Along the top: Drop Here shows where to drop files (anywhere on the window works),
then the file name, how long ago it was modified (for example Modified 3 hours 12 min ago,
refreshed every few seconds), and its size, line count, encoding and line endings. The line under them says whether
dropping is ready, or why it is not. Current dir is a drop-down of the last 12 folders
you used; the list and the current folder are saved in Config. Open chooses a
file (starting in the current folder), Explore opens the current folder in your
file manager, and Refresh reloads the loaded file from disk and rebuilds every tab.

When a file is loaded the tabs are built for you: Files holds Original (the file as it is on
disk), Sorted (the same code with the definitions sorted), Indexed (the file with an
index block added at the top) and Sorted Indexed (the sorted code with the block). Parts holds the smaller views: Index, Sorted Index, Vars, Calls,
Structure and About (Externals sits between Calls and Structure). Nothing is written to your Python file
until you press a Save button. Every text tab has a line-number column, a Copy
button and a Search box. A * after a tab title means its text has been edited and
is no longer what the app generated (or last saved, for the index tabs); it goes
away when the tab is rebuilt or the index is saved. The file's own encoding
(including a UTF-8 BOM) and line endings (CRLF, LF or CR) are kept when a file is
saved; both are shown under the file name. Click any Notes heading to
open its corresponding tab.

Search (every text tab): type in the box and every match is highlighted; the count
is shown beside it. Lines shows only the lines that contain a match and hides all
the others; untick it to see everything again. The text itself is not changed, so
Copy and the Save buttons still use the whole text. Press Enter to jump to the
next match. X in front of the box clears the search.

Files holds the four versions of the loaded file in a sub-notebook: Original, Sorted,
Indexed and Sorted Indexed. The last one you used is remembered.

Original: The file exactly as it was when loaded. This view is read-only. Save File writes
this text back over the loaded file, so the original can always be restored; a
timestamped copy of what was there is made first (see Backups). Reloading the file (Open or Refresh)
makes a new original.

Sorted: The original code with its definitions sorted, without an index block. At module
level the classes are sorted by name and functions keep their order; inside a
class the methods are sorted by name. Comments and spacing are kept. Only
definitions that sit next to each other are reordered, so a statement is never
moved past code that uses it. With sort_flag on (Config) a leading _ is ignored
when sorting.

Save File overwrites the loaded file with this text (the old file is copied to
Backups first). Save Sorted writes a new file beside it with -sorted added to the name, for
example tool-sorted.py. Sort Original File builds this tab and Sorted Indexed
again from the Original tab. You can edit the text here.

Indexed: The file with a generated index block added just before the first import (a
from __future__ import stays above it, as do a shebang line, a coding line and the
module docstring). The block holds source_file, source_modified and depth_index, a
triple-quoted string with the index lines. The line numbers in it match this tab.

Save File overwrites the loaded file with this text (the old file is copied to
Backups first). Save Indexed writes a new file beside it with -indexed added to the name. Insert
Index replaces the block after you have edited the text; only the text between its
begin and end marker lines is replaced. You can edit the text here.

Sorted Indexed: The sorted code with an index block, built the same way as Indexed. Save File
overwrites the loaded file with this text (the old file is copied to Backups first).
Save Sorted Indexed writes a new file beside it with -sorted-indexed added to the name. Insert
Index replaces the block after you have edited the text.

Ai is a prompt manager: you assemble a prompt from parts of your code and notes, then
copy it into an AI chat.

Left side, Sources: one tab for the loaded file and each of its views (Original first,
then Sorted, Indexed, Sorted Indexed, Index, Sorted Index, Vars, Calls, Externals),
then one tab for every <name>.ai.txt file that sits in the same folder as the loaded
file. Only files named <name>.ai.txt are listed, so ordinary .txt files are left
alone. Rescan .ai.txt reads the folder again. Every source has line numbers, Copy and
Search like the other tabs.

Select text in any source and press Add Selection: the text is added to the prompt
with a heading that names the file and the line numbers, for example

tool.py [Indexed] lines 40-72. It goes in at the cursor in the prompt, or at the

end until you click inside it, so you can thread pieces in and out of your own words.

A whole file is never pasted into the prompt: it has to be uploaded to the AI. Add
Whole File (upload) puts a copy of that source in the upload folder (prompts/upload
beside the program), lists it under Files to upload, and writes the line [Attached
file, uploaded with this prompt: name] into the prompt. Open Upload Folder shows the
folder so you can select the files and drag them into the chat. The Original copy is
the file as it was loaded, with its own encoding and line endings. Remove Selected and
Clear Uploads empty the folder again.

Right side, the prompt: type in it as well. Copy copies all of it. Prompt name and Save
Prompt write it as prompts/<name>.ai.txt beside the program (an existing prompt asks
before it is replaced). Saved prompts lists them; select one and press Load Selected
to continue working on it. Clear empties the prompt after asking.

Parts holds seven smaller views in a sub-notebook: Index, Sorted Index, Vars, Calls,
Externals, Structure and About. The last one you used is remembered.

Index: the index of the Indexed tab: first the source file name and its modified
time, then one line per function or class. Outside functions come first, sorted by
name, then each class with its functions indented under it, also sorted by name.
Each line ends with the line number where it starts; a class shows its first and
last line. Double-click a line to jump to it in the Indexed tab. Make Index builds
it again and writes <name>.index.txt and <name>.index.json beside the file (the json
is for other programs). Save Index writes your edits over the txt file.

Sorted Index: the same for the Sorted Indexed tab; double-click jumps there. Files
are <name>-sorted.index.txt and <name>-sorted.index.json.

Vars: the variables, in the same order as Index. Module variables first, each with
its annotation, a short value and the line numbers where it is assigned; then
functions (names only, nested ones indented), then classes with class variables,
self. attributes and methods. The index block itself is left out. Save Vars writes
<name>-vars_index.txt. Double-click jumps to the first line number.

Calls: which def calls what. Each def or class is listed (functions by name, then
classes), and under it, indented, each call it makes sorted by name with where the
callee comes from in brackets: this file (with its line), this class, an import
(shown as the import line that supplies it), a builtin, a local variable or
parameter, or unknown. A call that cannot be traced is marked unknown, and if the
file has a star import it says the name may come from that. xN is how many times
the call appears. Calls made outside any def are under (module level). Make Calls
rebuilds it; Save Calls writes <name>-calls_index.txt.

Externals: the index of everything the file uses from outside. Each import is listed
with its origin and line; indented under it are the names called through it, how
many times (xN) and which defs call them (Class.method form). An import whose call
does not show the source file (from x import name, or from x import *) is marked
CAUTION. Calls that cannot be traced to an import, this file or a builtin are listed
last under Unknown source. Make Externals rebuilds it; Save Externals writes
<name>-externals_index.txt.

Structure: the table lists every class and function of the Indexed tab: Depth, Type,
Name, Parameters, Returns, Decorators, Line, End and Parent. It starts sorted by
name; click a column heading to sort another way. The CSV, HTML and JSON buttons at
the top right export the table as it is shown. Click a row to see that function in
a panel over the right half of the window, with its code, signature and line
numbers. Copy copies the code; Close or Esc shuts the panel, and so does leaving
the tab. Hold Shift or Ctrl while clicking to select several rows for publishing
without opening the panel. The table is what HTML Publish uses. If the text has a
syntax error a message shows it and the table is left empty.

About: read-only facts about the program and the loaded file. The folders in use;
cautions (below);
statistics (lines, classes, functions, methods, average, median, shortest and
longest def length, defs over 50 lines, parameters per def, docstring and return
type coverage, decorators, variable counts, call sites); and a report on imports.
Cautions: a def or class defined twice in the same scope is a MAJOR caution, because
the later one silently replaces the earlier; property setters, @overload and
@x.register are not counted. Imports that do not name the source file are a
Caution (star imports are treated the same as bare names). The same summary is shown
in red under the file name, so it is seen without opening About.
The same cautions are written as comment lines at the top of the index block (they
are replaced with it), and as a coloured banner on the .code.html page.

The import report judges whether a call shows which file a def came from.
import module and import module as alias are clear: a call reads os.path.join or
np.array. from module import name is flagged as a documentation fail, because a
call reads Path(...) and the source file is not visible; from module import * cannot be
traced at all. The report lists each import with its origin (standard library or other),
its line, how often it is used, the percent that are clear, and imports that are
never used. Make About rebuilds it and Save About writes <name>-about.txt.

Choose the report folder and publish the structure table as an HTML page. The
folder is saved in Config. If the window is small, scroll this tab.

Publishing also makes a second page, <name>.code.html, in the same folder. It
lists the same entries in index order (outside functions by name, then each class
with its functions under it). Under each one the Python code is hidden; press the
V button, or click the line, to open it, and press it again to close it. Expand
all and Collapse all are at the top. Every entry has an anchor named after its
first line, such as #L29, and a # link beside it; a web address ending in
page.code.html#L29 opens the page with that function's code already open, which
works for a link on GitHub Pages or any other web host. The code is the text of the Indexed tab when
the Structure table was last built.

Publish + Update Index also writes index.html, a list of every .html page in the
folder and its subfolders except index.html itself. Open Index rebuilds
index.html and opens it in your browser. Selected rows only publishes just the
rows you have selected, on both pages; with no rows selected the code page is not
made. Open Publish Folder shows the folder in your file manager.

The list at the bottom shows every file in the report folder and its subfolders,
with the modified time and size. Double-click a file to open it; Refresh List
reads the folder again. Publishing makes reports; it does not run or change the
source.

Dropping files on the window does all of this for each file: it builds every tab,
writes <name>.index.txt, <name>.index.json and <name>-vars_index.txt beside the
file, publishes both pages, and updates index.html once at the end. A dropped
folder processes every .py and .pyw file directly inside it (not its subfolders),
so one drop can make the pages for a whole project. Dropping works on Windows
and needs no extra package. In an embedded host, the host calls process_files()
with the paths.

Every time Save File overwrites your Python file, the old file is first copied to
the backups folder beside the program as <name>.<date-time>.bak, and recorded in
backups.json with where it came from and why. The list shows each backup with its
time, size, original file and reason, newest first. Loaded file only shows just the
backups of the file that is loaded. Select one and press Restore Selected: after a
confirmation the file as it is now is backed up too, then the chosen backup is
copied over the original, and the tab is reloaded if it is the loaded file. A .bak
with no record in backups.json is listed but cannot be restored automatically.
Open Backups Folder shows the folder; Refresh List reads it again.

Last file shows the source file the app remembers. Current dir shows the folder
chosen at the top; the last 12 are saved with it. HTML publish directory shows the
report folder, which you set on the HTML Publish tab. sort_flag, when ticked, makes
every sort ignore a leading _ in a name, so _helper sorts under h; it applies to
Sorted, both indexes, Vars and the Structure table. If you change it, press
Refresh to rebuild the tabs.

Nothing is written to the source file until you press a Save button. Save File
overwrites the loaded file, with a backup made first; the other Save buttons
write a new file beside it. Save Config writes the settings to the settings file at once (its path is shown above
the button). Settings are also saved when you open a file, publish,
apply UI Choices or close the app. Use UI Choices for appearance.

Choose the colour theme, density and window size. These settings control how the
app looks. File locations and options belong in Config.

Use the shared launcher to open registered applications, files, folders and
links. Opening a Gateway item is separate from processing the current file.

Examine the supplied code without modifying it.

Analyse the actual implementation rather than reconstructing it from conventional programming patterns.

Answer the relevant questions from the comprehensive code examination framework.

For every significant finding, distinguish between:

VERIFIED: Directly established from the supplied source code or actual test results

INFERRED: A reasonable interpretation that has not been independently verified

UNKNOWN: Information that cannot be established from the supplied material

ERROR: A demonstrable defect, with its location, cause, and consequences

RISK: A potential failure requiring additional evidence or testing

Identify the relevant function, variable, and source line whenever possible.

Do not invent missing code, dependencies, application behaviour, or test results.

Do not rename variables, rename functions, reorder code, remove comments, remove debugging statements, or suggest unrelated changes.

Preserve the existing architecture and implementation approach.

Do not generate replacement code unless specifically instructed.

Before recommending any modification, explain precisely which existing behaviour is affected, why the modification is necessary, and how the original functionality can be verified afterward.

The supplied code is the authoritative source. Missing information must be reported as missing, not replaced with assumptions.
